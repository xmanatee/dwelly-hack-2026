# Live voice demonstration: 2–3 minutes

[Project](../README.md) · [Recorded voice demo](voice-call.mp4) · [ElevenLabs agent setup](../examples/voice/README.md)

Use the existing implementation after the freeze. Do not change source, prompts, plans,
model configurations or submitted answers for this demonstration.

## What this demonstrates

A real ElevenLabs conversation calls the local `ask_dwelly` tool. The bridge gathers
scoped test records, runs the prepared demo plan and returns the reply to the same call.
The caller hears the response; the local capture records the context and action receipts.
The plan is a **fixture**, not a live model-generated decision. The investigator handoff
is simulated; no bank transaction or real operator transfer takes place.

```mermaid
sequenceDiagram
    participant U as Caller
    participant E as ElevenLabs
    participant L as Local ask_dwelly
    participant D as Scoped test records
    U->>E: Ask about the £350 transfer
    E->>L: request, caller_name, reference
    L->>D: Read available context
    D-->>L: Sent; receipt not confirmed
    Note over L: Prepared demo plan and mock handoff
    L-->>E: say + handoff_status=simulated
    E-->>U: Speak the reply
```

## Before going on stage

- Use the already configured ElevenLabs agent. Its client tool must be named
  **`ask_dwelly`**, with **Wait for response** enabled and the parameter contract in
  [agent setup](../examples/voice/README.md). A webhook tool is a different transport.
- Set `ELEVENLABS_API_KEY` and `ELEVENLABS_AGENT_ID` in the existing ignored `.env`,
  or export them locally. Do not overwrite other keys or display them on screen.
- The private-agent key needs ElevenAgents access. No Anthropic key is needed for
  this fixture voice demo. Internet, microphone permission and working audio are needed.
- Use headphones to avoid feedback. The local process opens an outbound connection;
  no tunnel, public server or phone number is required.
- On a fresh machine: install PortAudio, then `uv sync --locked --extra voice`.
  The prepared presentation machine already has ElevenLabs and PyAudio installed.

From the repository root, choose a fresh capture directory on every attempt:

```sh
uv run --no-sync dwelly-bot voice call \
  --scope voice-demo-transfer \
  --records examples/voice/records.json \
  --plan examples/voice/plan.json \
  --output ".cache/voice/live-$(date +%Y%m%d-%H%M%S)"
```

If required, append `--mic 'device name'` and `--speaker 'device name'`; names may be
substrings or device indices. Defaults use the system devices. Stop with Ctrl+C or
the agent's configured End call tool. Keep credentials and account dashboards offscreen.

## On-stage sequence

| Time | Show / say |
| --- | --- |
| 0:00–0:20 | “This is a live voice connection to our local case pipeline. This demonstration uses a prepared plan and synthetic records.” |
| 0:20–1:20 | Ask: “I'm Jamie Rowe. I sent £350 to Kestrel Joinery on 8 October and they say it hasn't arrived. Has it gone?” Wait for the tool-backed reply. |
| 1:20–2:10 | Show the new capture's `context.md`, `plan.json` and `result.json`: sent does not prove received; investigation is needed; handoff is simulated. |
| 2:10–2:40 | Show the separate [30 final challenge answers](../ANSWERS/README.md), generated by the actual Opus Planner. Clearly distinguish that model run from the fixture used for speech. |
| 2:40–3:00 | End the call and state the current boundary: real conversation, local test data, simulated banking effects. |

Stay within this scenario: the fixed plan does not recompute a decision for unrelated questions.

## Quick fallback

For a microphone problem, add `--text` to the same command and type the request. This
demonstrates a real provider/tool session but is **not** a microphone/audio demonstration.
If the provider is unavailable, show [the recorded voice call](voice-call.mp4), labelled
as a recording. Neither fallback proves a successful live audio session.

The no-provider preflight is:

```sh
uv run --no-sync dwelly-bot voice ask \
  --scope voice-demo-transfer --records examples/voice/records.json \
  --plan examples/voice/plan.json \
  --output ".cache/voice/preflight-$(date +%Y%m%d-%H%M%S)" \
  --request "Has my 350 pound transfer to Kestrel Joinery arrived?"
```

Expected: `status: answered`, a reply distinguishing sent from received, and
`handoff_status: simulated`. This offline path was checked during the documentation
review; a fresh provider/audio session was not started.

## Other test data and the model Planner

The voice runner accepts normalized JSON (`--records`) or a normalized SQLite table
(`--sqlite`, default table `context_records`). Required record fields are `id`,
`scope_id`, `available_at`, `kind`, `source`, `text`. A raw synthetic-bank database is
not interchangeable with that table, and the voice CLI has no `--dataset` or
`--planner-config` option.

The [synthetic bank runner](../local_testing/banking/README.md) and
[authenticated HTTP service](../docs/voice/README.md) already support the shared model
Planner. The HTTP route can be used with an already provisioned ElevenLabs webhook,
trusted session credentials and HTTPS, but it is a separate setup. Adding an Anthropic
key does not turn the client-tool fixture path into model-driven speech. No such wiring
is added after the freeze.

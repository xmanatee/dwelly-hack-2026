# 60-second storyboard

**Current recording target:** the working skeleton. Final Planner/voice footage remains a replacement slot, not a capability to narrate as complete.

| Time | Screen | Narration / point |
| --- | --- | --- |
| 0–8s | Incoming ticket or email fixture | “A service request arrives with incomplete context. We separate gathering facts, deciding what to do, and executing the decision.” |
| 8–18s | Architecture diagram; highlight the Planner | “The same decision component is designed for production requests and prepared hackathon cases.” |
| 18–30s | Run the ticket demo; open `context.md` | “Here is the exact context: source records and gaps. Future events and another customer's records are excluded.” |
| 30–40s | Open `plan.json` and `result.json` | “The current placeholder requests human review. These channel actions are simulated; their status is explicit.” |
| 40–52s | Run the calculation fixture and show the returned message | “This supplied plan calculates 150.00 and inserts the value into a simulated ticket reply. The arithmetic is real; the plan is a fixture.” |
| 52–60s | Second capture with the same receipt store | “Replaying the event reuses recorded receipts. Next we plug in the final Planner, entity data and real channels.” |

When the final Planner is implemented, replace the placeholder/fixture scene with its actual run, name the model and show the resulting plan. Voice is optional: only show a call as audio if it really uses the implemented speech path. Keep all changes within the same 60-second budget.

Record the working product, preserve genuine failures and follow the event's effective source/video freeze. [Video packaging checklist](README.md).
